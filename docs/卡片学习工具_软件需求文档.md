## 0. 背景与目标

### 0.1 为什么做这个工具

现有方案（尤其 Anki）存在三大痛点，本项目正是为解决它们而生：

| 痛点 | 用户感受 | 本工具的解法 |
|------|----------|--------------|
| **界面老旧** | "像政务系统，方块布局、堆砌文字" | 小清新、卡片式、留白充足、圆角柔和的现代 UI |
| **上手门槛高** | 学习曲线陡、概念繁杂（牌组/模板/字段/插件） | 打开即用，隐藏专业复杂度，术语降维 |
| **制卡繁琐** | 手动录入卡片耗时，是用户放弃的主因 | 一键导入文档（PDF/Word/文本）→ AI 自动生成卡片牌组 |

### 0.2 目标用户

- 学生（考研、考证、语言、医学、法律、编程等需要大量记忆的场景）
- 知识工作者（读报告/书籍/技术文档，想把要点沉淀成卡片）
- 终身学习者（碎片时间复习）

### 0.3 核心价值主张

> **把任何文档变成卡片，用科学的方法（主动回忆 + 间隔重复）真正记住它——界面好看，操作简单。**

## 1. 学习方法论内核（决定功能设计）

调研提炼出的科学共识，本工具的"灵魂"，所有功能围绕它设计：

### 1.1 三大核心原则

1. **主动回忆（Active Recall）**：先想答案再翻面，而不是"再读一遍"。检索越费力，记忆越牢。
   - 设计落地：卡片默认先显示问题，必须手动"翻面"才能看答案，并强制用户自我评分。
2. **间隔重复（Spaced Repetition）**：在"即将遗忘"的时刻复习，而非刚学过就反复看。复习间隔逐次拉长（1天→3天→7天→14天→30天）。
   - 设计落地：算法自动安排每张卡的下次复习时间，用户无需手动规划。
3. **原子化卡片（One Card, One Fact）**：一张卡只承载一个知识点，5~10 秒能回忆完。
   - 设计落地：导入文档时 AI 自动把长段落拆成原子卡片；也提供"一卡一义"的录入引导。

### 1.2 调度算法选型：FSRS

| 方案 | 结论 |
|------|------|
| 莱特纳盒（Leitner） | 经典、直观，适合手写/入门，但精度有限 → 可作为**可视化说明**呈现给用户理解 |
| SM-2（Anki 老方案） | 成熟稳定，但参数固定、不能个性化 |
| **FSRS（推荐）** | 当前最优：用 3 个数字描述每张卡（稳定性/难度/可提取性），根据用户真实复习记录**自动拟合参数**，可用"目标保持率"一个旋钮平衡复习量。Anki/RemNote 均已迁移 |

**决策：主算法采用 FSRS（开源，MIT 许可，有 rs/ts 多语言实现）。**
- 用户唯一需要理解的参数 = **目标保持率（Desired Retention，默认 90%）**，用一个滑块表达"想记多牢"即可。
- 四个评分按钮：**重来 / 困难 / 良好 / 简单**（Again/Hard/Good/Easy）。

### 1.3 卡片类型（MVP 聚焦）

| 类型 | 说明 | 优先级 |
|------|------|--------|
| **基础问答卡** | 正面问题 → 反面答案 | P0（核心） |
| **填空卡（Cloze）** | 一句话挖空一个关键词 | P0 |
| **开口卡（录音自评）** | 看提示 → 按住录音口头作答 → 回放 → 对比参考答案 → 自评 | **P0（新增，差异化核心）** |
| 图片遮罩卡（Image Occlusion） | 图上遮块记忆（医学生刚需） | P2（后置） |
| ~~反转卡~~ | 不作为一种卡类型，改为**所有卡片的通用翻转能力**（见 3.4） | 已并入翻转 |
| ~~选择题卡~~ | 4 选 1 | **降至 P2**：测的是再认（recognition）而非回忆（recall），与 1.1 主动回忆原则冲突 |

> **重要设计原则**：翻转是卡片的**底层属性**，不是一种题型。任意卡片都可一键翻转正反面，
> 避免用户困惑"反转卡和翻转按钮有什么区别"。

## 2. 产品范围与形态

- **PC 端**：Windows（当前开发）。技术栈 Flutter，架构预留 macOS / Linux 扩展空间（仅备案，暂不开发）。
- **手机端**：Android（当前开发）。架构预留 iOS / 鸿蒙扩展空间（仅备案，暂不开发）。
- **数据同步**：MVP 采用**手动同步**（导出/导入学习数据包，见 3.8）；账号云同步列入后续阶段。

### 2.1 技术形态（已确认）

采用 **Flutter 一套代码同时产出 Windows + Android 两端**。核心逻辑（FSRS 算法、数据层、拆卡引擎）与 UI 复用，两端仅做平台适配层。

### 2.2 平台适配层（Android）

| 维度 | Windows | Android | 为什么必须分开处理 |
|---|---|---|---|
| 数据目录 | exe 同级目录 | 应用私有目录（应用文档目录） | 手机没有「exe 同级」概念；私有目录不需要任何存储权限，也避开 Android 10+ 分区存储限制 |
| 文档导入 | 按扩展名过滤选择 | 系统文件选择器（SAF），**不做扩展名硬过滤**，选后校验后缀 | Android 按 MIME 类型过滤，`md`/`markdown`/`json` 常被系统文件管理器隐藏，用户会「选不到文件」 |
| 导出数据包 | 弹窗显示路径 + 打开文件夹 | **直接调系统分享**（微信/网盘/邮件） | 手机导出的文件落在私有目录，用户根本取不到；只给路径等于没给 |
| 打开文件夹 | explorer / open / xdg-open | 隐藏该入口 | Android 无对应能力，`Process.run` 在手机上会崩 |
| 字体 | 苹方（PingFang SC） | 系统默认中文字体 | 苹方只存在于 Apple 平台，指定了会走字形回退 |
| 卡包网格 | 2 列，比例 1.15 | 宽度 <400dp 时 2 列，比例 0.92（更高） | 手机宽度下原比例装不下「名称 + 副标题 + 进度条」，会溢出 |
| 问号浮层 | 悬浮展开 / 移开收起 | 点击展开 / 点空白收起；宽高按屏幕自适应，底部空间不足时向上展开 | 触摸端没有 hover；桌面 380 宽浮层在 360dp 屏上会撑出屏幕 |
| 安装包 | — | 正式 keystore 签名；arm64-v8a / armeabi-v7a / x86_64 + universal | 按 ABI 分包体积减半；正式签名保证后续版本可覆盖升级 |

**验收口径**：360×800dp（主流手机）与 320×568dp（老机型）两种尺寸下，四个主页面渲染无溢出 —— 由组件测试 `test/mobile_layout_test.dart` 守护。

## 3. 功能需求（分模块）

### 3.1 牌组管理（Decks）
- 创建/重命名/删除/归档牌组，支持**子牌组**（两层即可，避免过度复杂）。
- 牌组封面：支持选颜色 / emoji 图标 / 自定义图片（小清新风格的关键）。
- 首页以**卡片网格/列表**呈现牌组，展示：名称、卡片总数、今日待复习数、学习进度。

### 3.2 卡片录入

#### 3.2.1 卡片字段（默认模板）

除正面 / 反面两个必填字段外，默认模板**结构性地**包含以下字段（可留空，但结构必须存在）：

| 字段 | 说明 | 作用 |
|------|------|------|
| `Front` 正面 | 你看到什么 | 必填 |
| `Back` 反面 | 你要回忆什么 | 必填 |
| `Context` 语境 | 出处原句 / 例句 / 上下文 | **孤立知识点调不出来**——这是"认得但说不出"类问题的解药 |
| `Source` 来源 | 文档名 / 集数 / 时间戳 | 便于回溯与举证 |
| `Audio` 音频 | 参考答案发音（TTS 或录音） | 没有声音的口语卡价值减半，听得见才调得出 |

> 验收：新建卡片界面可见这三个字段；导入第三方牌组（.apkg / CSV）时自动尝试字段映射。

#### 3.2.2 录入方式
- **手动录入**：基础问答卡、填空卡、开口卡（支持富文本、图片、公式 LaTeX、音频）。
- **批量录入**：**仅导入文档**（CSV / Markdown / 纯文本）。**不做粘贴文本导入**——统一走文档，来源可回溯，格式规则只用记一套。
- **导入辅助**（v1.3 新增）：
  - 导入页提供**模板下载**：`CSV 模板`（表头 `front,back,context,source,tag,type,flipped` + 4 行示例）、`MD 规格`（给 AI 的拆卡铁律：一卡一义 / 答案≤9 词 / 必带语境 / 中文提问→外语回答 / 不生成选择题 / 正面独立；20–60 张且说明只启前 20）。
  - 关键位置提供**悬浮问号解释图标**：模板字段说明、文本格式说明（`!`/`！` 仅按首个切正反面；`;`/`；`/换行分卡）。
- **CSV 兼容性要求**（v1.3 新增）：
  - 编码自动识别：UTF-8（含/不含 BOM）、UTF-16 LE/BE；非 UTF 系（GBK/ANSI）明确提示转码，不静默导入乱码。
  - 表头支持中文别名：正面/问题→front、反面/答案→back、语境/例句→context、来源→source、标签→tag、类型→type、方向→flipped。
  - 分隔符自适应：`,` / `;` / Tab（部分 Excel 区域设置导出用分号）。
  - 解析失败时报错信息**回显读到的第一行**，便于用户自查。
- **录入引导**：
  - 提示"一卡一义"，过长时建议拆分。
  - **语块长度硬提示**：答案文本超过 **9 个词** → 温和提示"这张可能太长，考虑拆开"（不阻断输入）。
    理由：长卡 = 永远记不住 = 未来的 Leech。

### 3.3 文档导入 + AI 生成卡片（核心差异化功能）
用户上传文档 → 系统生成牌组。流程：

1. **上传**：支持 PDF、Word(.docx)、Markdown、纯文本、网页链接。PDF 自动提取文本（含 OCR 可选）。
2. **AI 分析**：识别文档结构，生成**章节大纲**，用户可选择"全篇"或"指定章节"生成。
3. **参数设置**：
   - 卡片密度：精简 / 均衡 / 详细
   - 答案详细度：简洁 / 标准 / 详细
   - 卡片类型：问答 / 填空 / 开口 / 混合（自动）
   - **提问语言 / 回答语言**（新增，关键）：明确"你想被考的是哪种语言？"
     对语言学习材料**默认设为「母语提问 → 外语回答」**。
     理由：从英文文档自动生成的卡，默认会变成"英文 → 中文"，恰好是错的方向——
     练的是阅读认词，对开口毫无帮助。
     *验收*：导入英文材料并选"中文提问"后，抽样卡的正面是中文。
4. **方向确认（新增）**：预览区**显示 3 张样例卡的正面**，并询问"你想被考的是哪一面？"，支持一键翻转。
   *验收*：翻转后历史复习记录不丢失。
5. **生成与预览**：生成卡片后进入**可编辑预览态**，用户可逐张删除、修改、补充后再确认入库。
6. **分批释放（新增，防崩溃关键）**：

   > 一次性生成几百张卡入库 = 三天后积压爆炸 = 用户消失。这是"AI 生成卡片"卖点自带的毒性。

   - 生成 300 张 → **默认只启用前 20 张**进入学习队列，其余存为"待启用"。
   - **每日自动释放一批**（v1.3 落地规则）：启动时检查，每天至多补一批；积压 >60 时不补（与 C1 联动）；仅当该卡包"已启用且未学过的卡"少于每日新卡上限（8）时才补下一批，不会一次性放完。
   - 卡包页提供**手动释放**入口：「还有 N 张没启用 · 现在就放一批」。
   - 首页明确显示 **"已启用 20 / 共 300"**。
   - *验收*：生成 300 张后，今日新卡数 = min(新卡上限, 已启用数)；未释放的不出现在学习队列；次日启动自动补一批。

> 技术说明：本地可先做"结构化文本拆分"降级方案（按标题/列表/定义模式拆卡），联网 AI 作为增强。

### 3.4 学习 / 复习（核心闭环）

#### 3.4.1 基础流程
- **今日学习**：首页明确展示"今日待复习 N 张"+"今日新卡 M 张"，一键开始。
- **学习流程**：出题 → 用户心中作答 → 翻面看答案 → 自评（重来/困难/良好/简单）→ 下一张。
- **方向可见 + 一键翻转**：编辑器与学习页显式标注「**正面 = 你看到什么** / **反面 = 你要回忆什么**」，
  中间提供互换按钮，可一键翻转（翻转后复习记录保留）。
  > 方向是核心决策，不能因"隐藏复杂度"而藏起来——语言学习者 90% 的失败是把卡片做成"英文 → 中文"。
- **新卡学习步骤**：新卡先在当天用短间隔过一遍（默认 `1min → 10min`），答对才进入正式复习队列。
- **自定义学习（临时突击）**：考前可按"牌组/标签/错过的卡"临时加练，不影响正式进度。

#### 3.4.2 防崩溃护栏（P0，不改则产品会"静默失败"）

> **静默失败的定义**：用户不会报错、不会卸载，只是第 9 天打开看到 300 张待复习，然后永久消失。

| 编号 | 机制 | 规则 | 验收 |
|------|------|------|------|
| **C1** | **新卡上限 + 积压联动** | 新卡上限**默认 8**（不给 20 或"不限"）；复习上限默认**不设**（9999，还债不许设上限）。<br>**积压保护**：待复习 > **150** → 自动暂停新卡，首页明示"今天不加新卡，先清完 150 张"；积压 < **60** 自动恢复 | 造 300 张到期卡 → 新卡入口置灰且首页出现降级提示；清到 60 以下自动恢复 |
| **C2** | **断卡恢复** | 距上次学习 ≥ **3 天** → 回归首日**只清复习，不加新卡**。<br>首页文案换成"**回来就好，今天先还债**"（禁用"你已断更 3 天"这类惩罚性表达） | 注入 last_study_date = 4 天前 → 打开后新卡数为 0，复习正常 |
| **C3** | **Leech 顽固卡处理** | 单卡 Again 累计 ≥ **4 次** → 自动暂停，提示两个动作：**改写** 或 **删除**（"改写"直达编辑器）<br>理由：连错 4 次说明**卡片写坏了**（太长/太抽象/无语境），不是用户记性差，继续刷只会消耗意志力 | 连续 4 次 Again 后该卡不再出现，且出现在"待处理"列表 |
| **C7** | **每日时间预算** | 设置项：每日学习时长目标（分钟），**默认 10**。<br>首页显示"**今日约 9 分钟**"（按剩余卡数 × 历史平均单卡耗时估算）；超过预算时提示"今天够了，明天再来"<br>理由：真实约束是**分钟**不是张数（"睡前只有 10 分钟"） | 首页出现预计用时；超预算时给出提示 |
| **C8** | **快速复习模式** | 首页除"开始学习"外，另给一个「**只清复习（N 张）**」入口；进入后新卡一律不出现 | 该模式下新卡数为 0，退出后进度正确保存 |

> **护栏总原则**：与张数上限并行，谁先到算谁。目标是**在用户要崩之前替他踩刹车**。

#### 3.4.3 开口卡（录音自评）——差异化核心

> 整套学习动作里只有"看"和"想"，**没有"说"**——而语言学习的核心动作就是说。
> 真实案例证据：学习者病灶是"装配成句"（12 段自述只有 1 句完整），看卡片永远练不到这一层。

流程：
1. 正面显示提示（中文场景 / 音频 / 图片）
2. **按住录音**，用户口头作答（显示倒计时，如 30 秒）
3. 回放自己的录音
4. 播放参考答案音频，对比
5. 自评（重来 / 困难 / 良好 / 简单）→ 进入 FSRS 调度

> **为什么值得做**：这是 Anki 没有的能力（需装插件才勉强实现）。做出来 Hermes Cards 才有真话可讲：
> 「别人让你记住，我们让你说出来。」
> *验收*：能录、能回听、能对照参考音频、能自评；录音文件随数据包一并导出/合并。

### 3.5 统计与激励

**激励型指标**（已有）：
- **复习热力图**（GitHub 风格日历，激励效果好）。
- **连续打卡 Streak** 天数。
- **保持率 / 学习量曲线**，按牌组拆分。
- 未来复习量预测（接下来 7 天的每日待复习数）。

**诊断型指标**（新增，补齐"提前预警崩溃"的能力）：

| 指标 | 意义 |
|------|------|
| **成熟卡正确率** | 低于 **80%** 说明新卡加太快或卡片质量差——**唯一能提前预警崩溃的指标** |
| **Leech 数量** | 卡片写坏的体温计 |
| **实际用时 vs 预计用时** | 校准 C7 的时间估算准确度 |

> 这三个数也是导师 / 用户每周复盘时真正会看的。

### 3.7 设置

#### 3.7.1 默认值表（这组数字决定成败）

| 参数 | 默认 | 说明 |
|------|------|------|
| 每日新卡上限 | **8** | 不是 20。8×7≈56 张/周，与"每天提取 3–5 个知识点"的节奏匹配 |
| 每日复习上限 | **9999（不限）** | 还债不许设上限 |
| 目标保持率 | **0.90** | 0.95 复习量暴涨，0.85 调不出来 |
| 新卡步进 | **1m / 10m** | 新卡当天至少过两遍 |
| 毕业间隔 / 简单间隔 | **3 天 / 4 天** | — |
| Leech 阈值 | **4 次 → 暂停** | — |
| 积压暂停 / 恢复阈值 | **150 / 60** | — |
| 每日时间预算 | **10 分钟** | 与张数上限并行，谁先到算谁 |
| 默认主题 | 浅色 + **夜间模式** | 复习大量发生在睡前，**夜间模式是刚需不是偏好** |
| AI 生成首批启用量 | **20 张** | 见 3.3 分批释放 |

#### 3.7.2 设置项清单
- 目标保持率滑块（默认 90%）。
- 每日新卡 / 复习上限。
- **学习步进参数（C6，需暴露可调）**：新卡步进、毕业间隔、简单间隔。
  放在"设置 → 学习"（渐进披露，不进主界面），改后立即对新卡生效。
- **每日学习时长目标（分钟）**，默认 10。
- 主题：浅色 / 深色 / 跟随系统（**夜间模式为刚需**）。
- 字体大小、复习卡片翻面动画开关等。

### 3.8 数据与同步
- **MVP 阶段：纯本地 + 手动同步**（无账号体系）。
  - 学习记录、卡片牌组均存本地；支持一键**导出/导入学习数据包**（含卡片、进度、复习记录）。
  - 用户在 PC 与手机间通过文件（微信/网盘/USB 等）手动传输数据包完成同步。
  - 导入时做**智能合并**：以卡片为最小单位去重合并，两边各自新增的卡片和复习进度都保留，不互相覆盖。
- **本地存储形态（v1.3 确认）**：**JSON 单文件存储**（`hermes_cards.json`，含 decks/cards/reviewLogs/settings），替代原 SQLite 方案。理由：纯 Dart 实现、跨端一致、可脚本直接验证、无 sqlite3.dll 等原生依赖问题。
  - **多实例保护**：写盘前比对文件 updatedAt，发现被其它实例改过先按 id 合并（同 id 取较新），再写入——防止多开窗口互相覆盖丢数据。
  - 设置页提供**数据位置**入口，可一键打开数据文件所在文件夹。
- **导入后校验**：导入完成立即回读核对数量，对不上则提示用户关掉多余窗口。
- **演示数据**：首次使用可一键装载/清除演示数据（3 卡包 / 18 卡 / 含到期与新卡），便于体验完整闭环。
- **后续阶段：账号云同步**（待开发，见 6.6）。
- 兼容导出格式：.apkg、CSV、Markdown、JSON，避免锁定、方便迁移。

### 3.9 音频能力（L2 · 一等公民）

- 支持 **TTS 生成** / **用户录音** / **批量为选中卡片配音** / **离线播放**。
- 音频字段参与**搜索与导出**。
- 理由：没有声音的口语卡，价值减半——听得见才调得出。
- *验收*：选中 20 张卡可一键生成音频；导出 .apkg 时音频不丢。

## 4. 交互与视觉设计（重点回应"老气"痛点）

### 4.1 设计原则
1. **小清新**：柔和低饱和配色（薄荷绿 / 淡蓝 / 奶白为主色，莫兰迪色系）、圆角卡片、充足留白、克制的阴影。
2. **一屏一任务**：每个界面只做一件事，不堆砌信息。
3. **零专业术语**：不出现"牌组模板/字段/卡片类型预设"等 Anki 黑话，用"卡包""卡片"等直觉词汇。
4. **渐进披露**：高级功能（标签、参数、同步）收进设置，默认不打扰。

### 4.2 关键界面清单（MVP）
- 首页（牌组墙 + 今日任务卡）
- 牌组详情（卡片列表 + 学习入口）
- 卡片编辑器（录入/预览）
- 文档导入向导（3 步：选文档 → 参数设置 → 预览确认；CSV 直达预览）
- 学习界面（核心：翻面 + 四键评分）
- 统计页（热力图 + 曲线）
- 设置页

### 4.3 视觉风格关键词
小清新 / 卡片化 / 圆角 / 留白 / 柔和渐变 / 无边框式按钮 / 轻动效（翻面翻转、评分微动效）

## 6. 已确认的产品决策（v1.1 定稿）

以下决策已经用户确认，作为开发的**固定基准**。后续如需变更，须明确记录并更新本表。

| # | 决策项 | 确认结论 |
|---|--------|----------|
| 6.1 | **技术形态/技术栈** | **Flutter 一套代码同时产出 Windows + Android 两端**。理由：开发效率高、UI 一致性好、跨端成本最低。 |
| 6.2 | **同步方案** | **MVP 用"手动同步"**：本地为主，导出/导入学习数据包（卡片+进度+复习记录），经文件在两设备间手动传输、智能合并。**账号云同步列入后续阶段**，当前不开发。 |
| 6.3 | **AI 生成卡片** | **先做纯本地规则拆分**（免费、零依赖、可离线）：按标题/列表/定义/填空等结构化模式拆卡。**联网 AI（大模型 API）列为后续增强**，预留可插拔接口，暂不接。 |
| 6.4 | **平台范围** | **当前仅开发 Windows + Android。** 其余平台（macOS / Linux / iOS / 鸿蒙）**当前只出设计方案，不开发**，代码架构需预留跨平台扩展空间。 |
| 6.5 | **产品命名** | 采用 **「Hermes Cards」**。 |
| 6.6 | **本地存储形态（v1.3 新增）** | **JSON 单文件存储**，弃用 SQLite。实测 Windows 端 sqlite3.dll 依赖缺失导致数据库从未打开（首页假死），JSON 方案无原生依赖、跨端一致、可脚本验证。 |
| 6.7 | **导入入口（v1.3 新增）** | **仅文档导入，砍掉粘贴文本导入**。统一入口、统一格式规则、来源可回溯。 |

### 6.6 后续规划项（本次不开发，仅备案）
- 账号体系 + 云同步
- 联网 AI 文档生成卡片（大模型 API，支持自定义 Key）
- macOS / Linux / iOS / 鸿蒙 客户端（各平台届时按本架构出设计方案）
- GBK/ANSI 编码 CSV 的原生支持（当前提示用户转码为 UTF-8）

## 8. 设计护栏总纲（v1.2 核心精神）

> **Anki 的问题是"太难用"，但 Hermes Cards 要小心走向另一个极端——
> 太好用，以至于用户轻松生成 800 张卡，然后在第 9 天崩溃退出。**

真正决定成败的不是**生成能力**，是**限制能力**：

- 限制每天进来多少（C1 新卡上限 8 + 积压保护）
- 限制卡片能有多长（L3 语块 >9 词提示）
- 在用户要崩之前替他踩刹车（C2 断卡恢复 / C3 Leech / L5 分批释放）

把这些做进去，这个工具才有机会陪一个人跑完 8 个月。
